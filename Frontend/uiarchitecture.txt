### 6. COMPONENT DEFINITIONS

**KanbanBoardComponent:**
- Purpose: Main container for three-column kanban layout
- Props: columns (array), tasks (array), loading (boolean), error (string)
- State: draggedTask, columnData, isLoading, errorMessage
- Events: onTaskMove, onTaskCreate, onTaskUpdate, onTaskDelete
- API Binding: GET /api/tasks, POST /api/tasks, PUT /api/tasks/{id}

**KanbanColumnComponent:**
- Purpose: Individual column container (To Do, In Progress, Done)
- Props: columnId (string), title (string), tasks (array), count (number)
- State: isDropTarget, isLoading
- Events: onTaskDrop, onTaskAdd
- API Binding: None (receives data from parent)

**TaskCardComponent:**
- Purpose: Individual task display card
- Props: task (object), assignee (object), badges (array)
- State: isSelected, isEditing
- Events: onClick, onEdit, onDelete, onStatusChange
- API Binding: PUT /api/tasks/{id}, DELETE /api/tasks/{id}

**HeaderComponent:**
- Purpose: Top navigation with search and user actions
- Props: user (object), notifications (array)
- State: searchQuery, isSearchFocused
- Events: onSearch, onNotificationClick, onSettingsClick
- API Binding: GET /api/search, GET /api/notifications

**SidebarComponent:**
- Purpose: Left navigation menu
- Props: activeRoute (string), menuItems (array)
- State: isCollapsed, activeItem
- Events: onNavigate, onToggleCollapse
- API Binding: None (static navigation)

**AddTaskModalComponent:**
- Purpose: Modal for creating new tasks
- Props: isOpen (boolean), assignees (array)
- State: formData, isSubmitting, validationErrors
- Events: onSubmit, onCancel, onClose
- API Binding: POST /api/tasks, GET /api/users

### 8. API SUMMARY

**Available APIs:**
- GET /api/tasks → Retrieve tasks with filtering and pagination
- POST /api/tasks → Create new task
- GET /api/tasks/{id} → Get specific task details
- PUT /api/tasks/{id} → Update existing task
- DELETE /api/tasks/{id} → Delete task (soft delete)
- GET /health → Basic health check
- GET /health/detailed → Detailed system health

### 9. API TO UI MAPPING

**Component → API:**
- KanbanBoardComponent → GET /api/tasks (load tasks)
- AddTaskModalComponent → POST /api/tasks (create task)
- TaskCardComponent → PUT /api/tasks/{id} (update task)
- TaskCardComponent → DELETE /api/tasks/{id} (delete task)
- TaskDetailComponent → GET /api/tasks/{id} (get details)
- HeaderComponent → GET /api/search (search functionality)

### 10. API COMPATIBILITY

**Compatible:**
- Task CRUD operations fully supported by API

- User assignment supported through assignedTo field
- Status transitions supported through status field

**Missing:**
- Real-time notifications API not defined

- Bulk operations API not specified

**Transformations:**
- API uses UUID format, UI needs to handle string IDs
- API date format is ISO 8601, UI needs date parsing
- API status enum (TODO, IN_PROGRESS, DONE) maps to UI states
- API priority enum (LOW, MEDIUM, HIGH, CRITICAL) maps to UI badges

### 13. INTERACTION FLOWS

**User Action → UI → API:**

1. **Load Kanban Board:**
   - User navigates to kanban page
   - KanbanBoardComponent calls ngOnInit()
   - Component calls TaskService.getTasks()
   - Service calls GET /api/tasks
   - Response populates kanban columns

2. **Create New Task:**
   - User clicks "Add Task" button
   - AddTaskModalComponent opens
   - User fills form and submits
   - Component calls TaskService.createTask()
   - Service calls POST /api/tasks
   - Success updates kanban board

3. **Move Task Between Columns:**
   - User drags task card
   - TaskCardComponent emits move event
   - KanbanBoardComponent handles drop
   - Component calls TaskService.updateTask()
   - Service calls PUT /api/tasks/{id}
   - UI updates column counts

4. **Update Task Status:**
   - User clicks task card
   - TaskDetailComponent opens
   - User changes status dropdown
   - Component calls TaskService.updateTask()
   - Service calls PUT /api/tasks/{id}
   - Task moves to appropriate column
