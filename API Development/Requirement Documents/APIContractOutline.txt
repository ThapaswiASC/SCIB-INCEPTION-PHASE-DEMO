# API Contract Outline
## Task Management API System

### Version: 1.0
### Base URL: https://api.enterprise.com/v1
### Authentication: OAuth 2.0 Bearer Token

---

## API Overview

This document outlines the API contract for the Task Management System, focusing on the task creation endpoint as specified in DEMO-2350. The API follows RESTful principles and OpenAPI 3.0 specification.

### Global Headers
- **Authorization**: Bearer {token} (Required)
- **Content-Type**: application/json
- **Accept**: application/json
- **X-Correlation-ID**: {uuid} (Optional, for request tracing)
- **X-API-Version**: v1 (Optional, defaults to latest)

### Global Error Response Schema
```json
{
  "error": {
    "code": "string",
    "message": "string",
    "details": "string",
    "timestamp": "2024-01-01T00:00:00.000Z",
    "correlationId": "uuid",
    "path": "string"
  }
}
```

## Endpoints

### 1. Create Task

**Endpoint**: `POST /api/tasks`

**Description**: Creates a new task in the system with comprehensive validation and business logic processing.

**Request Headers**:
- Authorization: Bearer {token} (Required)
- Content-Type: application/json (Required)
- X-Correlation-ID: {uuid} (Optional)

**Request Schema**:
```json
{
  "title": {
    "type": "string",
    "required": true,
    "maxLength": 255,
    "minLength": 1,
    "description": "Task title",
    "example": "Complete project documentation"
  },
  "description": {
    "type": "string",
    "required": false,
    "maxLength": 2000,
    "description": "Detailed task description",
    "example": "Create comprehensive documentation for the new API endpoints"
  },
  "status": {
    "type": "string",
    "required": true,
    "enum": ["TODO", "IN_PROGRESS", "DONE", "CANCELLED"],
    "description": "Current task status",
    "example": "TODO"
  },
  "priority": {
    "type": "string",
    "required": false,
    "enum": ["LOW", "MEDIUM", "HIGH", "CRITICAL"],
    "default": "MEDIUM",
    "description": "Task priority level",
    "example": "HIGH"
  },
  "dueDate": {
    "type": "string",
    "format": "date-time",
    "required": true,
    "description": "Task due date (ISO 8601 format)",
    "example": "2024-12-31T23:59:59.000Z"
  },
  "assignedTo": {
    "type": "string",
    "format": "uuid",
    "required": false,
    "description": "User ID of assigned person",
    "example": "123e4567-e89b-12d3-a456-426614174000"
  },
  "tags": {
    "type": "array",
    "items": {
      "type": "string",
      "maxLength": 50
    },
    "maxItems": 10,
    "required": false,
    "description": "Task tags for categorization",
    "example": ["documentation", "api", "urgent"]
  },
  "metadata": {
    "type": "object",
    "required": false,
    "description": "Additional task metadata",
    "example": {
      "project": "API-2024",
      "department": "Engineering"
    }
  }
}
```

**Success Response (201 Created)**:
```json
{
  "id": "123e4567-e89b-12d3-a456-426614174000",
  "title": "Complete project documentation",
  "description": "Create comprehensive documentation for the new API endpoints",
  "status": "TODO",
  "priority": "HIGH",
  "dueDate": "2024-12-31T23:59:59.000Z",
  "assignedTo": {
    "id": "123e4567-e89b-12d3-a456-426614174001",
    "name": "John Doe",
    "email": "john.doe@enterprise.com"
  },
  "createdBy": {
    "id": "123e4567-e89b-12d3-a456-426614174002",
    "name": "Jane Smith",
    "email": "jane.smith@enterprise.com"
  },
  "tags": ["documentation", "api", "urgent"],
  "metadata": {
    "project": "API-2024",
    "department": "Engineering"
  },
  "createdAt": "2024-01-01T10:00:00.000Z",
  "updatedAt": "2024-01-01T10:00:00.000Z",
  "version": 1
}
```

**Error Responses**:

**400 Bad Request - Validation Error**:
```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Request validation failed",
    "details": "One or more fields contain invalid data",
    "timestamp": "2024-01-01T10:00:00.000Z",
    "correlationId": "123e4567-e89b-12d3-a456-426614174000",
    "path": "/api/tasks",

      {
        "field": "title",

        "value": ""

        "field": "dueDate",

        "value": "2023-01-01T00:00:00.000Z"
      }
    ]
  }
}
```

**401 Unauthorized**:
```json
{
  "error": {
    "code": "UNAUTHORIZED",
    "message": "Authentication required",
    "details": "Valid bearer token must be provided",
    "timestamp": "2024-01-01T10:00:00.000Z",
    "correlationId": "123e4567-e89b-12d3-a456-426614174000",

}
```

**403 Forbidden**:
```json

  "error": {
```

**Description**: Retrieves a specific task by its unique identifier.

**Path Parameters**:
- `id` (string, uuid, required): Task unique identifier

**Request Headers**:
- Authorization: Bearer {token} (Required)

- X-Correlation-ID: {uuid} (Optional)

**Request Schema**: N/A (No request body)

### 3. Update Task

**Endpoint**: `PUT /api/tasks/{id}`

**Description**: Updates an existing task with new information.

**Path Parameters**:
- `id` (string, uuid, required): Task unique identifier

**Request Headers**:
- Authorization: Bearer {token} (Required)
- Content-Type: application/json (Required)
- If-Match: {version} (Required for optimistic locking)
- X-Correlation-ID: {uuid} (Optional)

**Request Schema**: Same as Create Task, but all fields are optional

**Success Response (200 OK)**: Same as Get Task response

**Error Responses**:
- 400 Bad Request (Validation errors)
- 404 Not Found (Task not found)
- 409 Conflict (Version mismatch)
- 412 Precondition Failed (If-Match header mismatch)

---

### 4. Delete Task

**Endpoint**: `DELETE /api/tasks/{id}`

**Description**: Soft deletes a task (marks as deleted but preserves data for audit).

**Path Parameters**:
- `id` (string, uuid, required): Task unique identifier

**Request Headers**:
- Authorization: Bearer {token} (Required)
- X-Correlation-ID: {uuid} (Optional)

**Request Schema**: N/A

**Success Response (204 No Content)**: Empty response body

**Error Responses**:
- 404 Not Found (Task not found)
- 409 Conflict (Task cannot be deleted due to business rules)

---

### 5. List Tasks

**Endpoint**: `GET /api/tasks`

**Description**: Retrieves a paginated list of tasks with filtering and sorting options.

**Query Parameters**:
- `page` (integer, optional, default: 1): Page number
- `limit` (integer, optional, default: 20, max: 100): Items per page
- `status` (string, optional): Filter by task status
- `priority` (string, optional): Filter by task priority
- `assignedTo` (string, uuid, optional): Filter by assigned user
- `createdBy` (string, uuid, optional): Filter by creator
- `tags` (string, optional): Comma-separated list of tags
- `sort` (string, optional, default: "createdAt"): Sort field
- `order` (string, optional, default: "desc"): Sort order (asc/desc)
- `search` (string, optional): Full-text search in title and description

**Success Response (200 OK)**:
```json
{
  "data": [
    {
      "id": "123e4567-e89b-12d3-a456-426614174000",
      "title": "Complete project documentation",
      "status": "IN_PROGRESS",
      "priority": "HIGH",
      "dueDate": "2024-12-31T23:59:59.000Z",
      "assignedTo": {
        "id": "123e4567-e89b-12d3-a456-426614174001",
        "name": "John Doe"
      },
      "createdAt": "2024-01-01T10:00:00.000Z",
      "updatedAt": "2024-01-01T14:30:00.000Z"
    }
  ],
  "pagination": {
    "page": 1,

    "total": 150,
    "totalPages": 8,

    "hasPrev": false
```

## Security Considerations

### Authentication
- All endpoints require valid OAuth 2.0 Bearer token
- Tokens must be included in Authorization header
- Token validation includes signature verification and expiration check

### Authorization
- Role-Based Access Control (RBAC) enforced
- Permissions checked for each operation
- Users can only access tasks they have permissions for

### Data Validation
- All input data validated against schema
- SQL injection prevention through parameterized queries
- XSS prevention through input sanitization
- File upload restrictions and virus scanning

### Rate Limiting
- 100 requests per minute per user
- 1000 requests per minute per organization
- Rate limit headers included in responses

### Audit Logging
- All API calls logged with user context
- Sensitive data masked in logs
- Correlation IDs for request tracing

## Error Handling Standards

### Error Response Structure
All error responses follow a consistent structure with:
- Error code (machine-readable)
- Error message (human-readable)
- Detailed description
- Timestamp
- Correlation ID
- Request path
- Additional context (when applicable)

### HTTP Status Codes
- **200 OK**: Successful GET, PUT requests
- **201 Created**: Successful POST requests
- **204 No Content**: Successful DELETE requests
- **400 Bad Request**: Invalid request data
- **401 Unauthorized**: Authentication required
- **403 Forbidden**: Insufficient permissions
- **404 Not Found**: Resource not found
- **409 Conflict**: Resource conflict
- **422 Unprocessable Entity**: Business rule violation
- **429 Too Many Requests**: Rate limit exceeded
- **500 Internal Server Error**: Unexpected server error

### Error Categories
- **Validation Errors**: Input data validation failures
- **Authentication Errors**: Token-related issues
- **Authorization Errors**: Permission-related issues
- **Business Logic Errors**: Domain rule violations
- **System Errors**: Infrastructure or service failures
